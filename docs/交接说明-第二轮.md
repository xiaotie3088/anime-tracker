### P0-3 临时机翻译名（用户诉求 3）—— 工作量最大的一块

**数据层**（`src/server/schema.sql` + `db.ts` 的 `ensureColumn` 迁移，注意 `ensureColumn` 是幂等的）：

- `subject` 加两列：
  - `title_cn_source TEXT` —— `'official'` | `'machine'`（NULL 视为 official，兼容旧数据）
  - `title_cn_source_at TEXT` —— 机翻生成时刻（用于 UI 提示与"要不要重翻"）
- 关键规则（**必须写进验证项**）：
  1. 官方中文名（`bangumi` / `bangumi-data` / `yuc`）**永远覆盖**机翻名，并把 `title_cn_source` 改回 `'official'`。
  2. 机翻名**不得**进入 `fieldSources`（那个字段是给官方源用的）；或者引入新的 `SourceId`
     （`SOURCES_IDS` 加 `'mt'`，标签「机器翻译（临时）」），二选一并统一。
  3. 机翻名只写进 `title_cn`，**同时把原名保留在 `aliases`**，保证搜索仍能用原名命中。
  4. 已经有官方中文名的**不要翻**；原名里已经含中日汉字的**不要翻**（例如 `夏日 The Animation`，
     直接可用）；`title_original` 是纯拉丁文（`DARK MACHINE THE ANIMATION`）的不要机翻成中文。
- **新增** `src/providers/mt.ts`（机翻 provider，实测可用方案见第五节 4）：
  - 主用 **Bing 翻译（cn.bing.com）**：先 GET `https://cn.bing.com/translator`，
    从 HTML 里正则取 `params_AbusePreventionHelper = [<key>,"<token>",<ttl>]`、
    `IG\s*:\s*"([^"]+)"`、`data-iid="([^"]+)"`，然后
    POST `https://cn.bing.com/ttranslatev3?isVertical=1&IG=<ig>&IID=<iid>`
    body `fromLang=ja&text=<原文>&to=zh-Hans&token=<token>&key=<key>`
    （`content-type: application/x-www-form-urlencoded`，带 `referer: https://cn.bing.com/translator`）。
    token 有效期约 1 小时（响应里第三个值是 TTL 毫秒），**进程内缓存复用**，
    并且**第一次要抓 650KB 的 HTML 页**，所以一次会话翻一批，别一条一抓。
  - 兜底 **MyMemory**：`https://api.mymemory.translated.net/get?q=<原文>&langpair=ja|zh-CN`
    （免费额度有限、质量明显更差，只在 Bing 挂掉时用）。
  - 限速：每条约 0.7 秒间隔即可；实测 18 条 31 秒。
- **新增** `POST /api/translate`：入参 `{ season?, limit?, force? }`，
  返回 `{ translated: [{ key, titleOriginal, titleCn }], skipped, failed }`。
  前端按钮叫「补全中文名（机翻）」。
- 前端展示：机翻名的条目加 `tag-warn` 标签「临时机翻」，
  并在 tooltip 写「官方译名一到，一键更新会自动替换」。

### P0-5 「记录消失」（用户诉求 5）

- 已查清的**不存在的数据丢失路径**（不要重复怀疑）：
  - `my_anime` / `schedule_override` 是用户数据；`syncSeason` 只做 upsert，**从不 DELETE**。

- **最可能的真实原因（要在代码里验证并让它可见）**：
  1. **季度自动归档**：`autoArchiveFinished()` 会把「`status='finished'` + `watched_eps≥1` + 没看完」
     的追番自动挪进 `backlog`。用户加完番、同步一两次、下次进来就在「追番中」看不到它了
     —— 观感就是"记录消失"。这个行为是决策记录 **D6/T8 明确要的**，不能删，
     但**必须让它可见**：同步报告里列出被移动的番名，前端 toast + 「我的追番」页顶部提示。
  2. **搜索添加的番不在"全季总览"里**：`/api/search/import` 用 `season=null` 落库，
     全季总览按 `WHERE s.season = ?` 过滤，所以从搜索加进来的番**只在「我的追番」里可见**。
     用户如果只在总览页找，就会觉得"没了"。→ 建议：导入时**尽量回填 season**
     （AniList 搜索结果里带 season/seasonYear 时用它），或在总览页加"不在本季的我的番"分组。
  3. **当季条目 `status='unknown'`（实测 16 部）** 时归档规则会怎么表现，
     要在 `core/backlog.ts` 里确认一遍并补测试。
- **再加两道保险（P0-5 顺手做）**：
  - 启动时（`migrate` 之后）**自动备份** `data/anime.db` → `data/backups/anime-YYYYMMDD-HHmm.db`，
    只保留最近 N 份（比如 20 份）；同步前再备份一次。
  - 新增 `GET /api/export`（导出 `my_anime` + `schedule_override` + `change_log` 的 JSON），
