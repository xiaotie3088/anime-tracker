# 交接说明：在新对话里怎么继续这个项目

> ⚠ **这份是第一轮的文档，已不是最新入口。**
> 请先看 **[交接说明-第四轮.md](交接说明-第四轮.md)**（自包含：硬约束、现状、坑、待办全在里面）。
> 本文保留作「验证习惯」与「最容易改坏的地方」的细读版 —— 那两节仍然有效。

这份文档是为了解决一个问题：**AI 对话没有长期记忆，新开一个对话它就什么都不知道。**
下面给出可以直接复制粘贴的开场白，以及新会话必须先知道的关键约束。

---

## 一、最省事的用法：直接复制这段开场白

> 我在 `D:\AI\anime-tracker` 有一个叫「新番追番日历」的项目，请先读这几个文件再动手：
> `README.md`、`docs/决策记录.md`、`docs/sources.md`。
>
> 项目现状：TypeScript 全栈 + Node 24 原生跑 TS（**没有构建步骤**）+ `node:sqlite`，
> 前端是 `web/` 下的原生 ES 模块 SPA。数据源已接三个：bangumi-data、yuc.wiki、AniList；
> 另有 Bing/MyMemory 机翻兜底（`src/providers/mt.ts`）。
> 核心约束（详情见 docs/决策记录.md）：
> - 时间一律存 ISO8601 UTC；`subject` 上同时保留 `broadcast_weekday_jst`（放送日历归属）
>   与字面 `broadcast_time_jst`（如 `"24:30"`）。**禁止**用「UTC 转本地取星期」算归属，
>   深夜番会整体错位一天。
> - 改代码前后都要能通过：`pnpm exec tsc --noEmit`、`node scripts/verify.ts`（离线，102 项）、
>   `node scripts/verify-api.ts`（需先启动服务，28 项）。
> - **绝对不要用 PowerShell 的 `Get-Content`/`Set-Content` 改源码**（PS 5.1 默认 ANSI，
>   会把中文变成乱码；改源码请用编辑工具）。同理：源码必须 UTF-8 **无 BOM**。
> - `desktop/` 和 `scripts/` 下的启动脚本必须保持纯 ASCII（原因见 desktop/README.md）。
>
> 我想做的是：<在这里写你的需求>

把最后一行换成你的需求即可。如果只是小改动，前三段可以省略，但**读文件那一句一定要留**。

## 二、更省事的用法：只说要什么

如果你懒得多写，下面这种表达也够，因为项目里有文档、AI 读了就知道：

| 你想做的事 | 可以这样说 |
|---|---|
| 加功能 | 「在 `D:\AI\anime-tracker` 里加一个 X 功能，先读 README 和 docs/决策记录.md」 |
| 修 bug | 「`D:\AI\anime-tracker` 的周视图有个问题：……。先跑 verify.ts 和 verify-api.ts 确认现状」 |
| 只问不改 | 「读一下 `D:\AI\anime-tracker\docs\决策记录.md`，告诉我为什么选 undici 而不是全局 fetch」 |
| 接新数据源 | 「给 `D:\AI\anime-tracker` 接第 4 个数据源：B站 PGC。参考 `src/providers/yuc.ts` 的写法，先跑 probe-sources.ts 确认接口」 |
| 做界面改动 | 「改 `D:\AI\anime-tracker\web\` 里的界面：周视图我想……。改完跑 verify-api.ts」 |

**关键技巧：把项目路径写在第一句，并明确要求先读文档。** 这两件事能省掉大量来回解释。

## 三、新会话必须知道的硬约束

### 1. 环境

- Node ≥ 22.18（本机 v24.18），pnpm 11，Windows。
- **没有构建步骤**：`node src/server/server.ts` 直接跑 TS（Node 原生类型擦除）。
  因此代码里不能用 `enum`、`namespace`、构造函数参数属性（tsconfig 开了 `erasableSyntaxOnly` 强制）。
- 依赖只有 3 个：`zod`、`undici`、devDependencies 里的 `typescript` + `@types/node`。
  **不要引入框架/打包器**，那会破坏「装完依赖就能跑」这个特性。

### 2. 数据

- 数据库 `data/anime.db`（SQLite，用 Node 内置 `node:sqlite`，**不要换成 better-sqlite3**）。
- 用户数据（追番列表、进度、补番库）**不可重建**，改 schema 要写迁移
  （参考 `db.ts` 里的 `ensureColumn`）。
- `data/` 下的快照与缓存可随时删除重建。

### 3. 数据源现状（详见 docs/sources.md）

| 源 | 状态 | 注意 |
|---|---|---|
| bangumi-data | ✅ 可用 | 7.8MB，落盘缓存 12h；`broadcast` 是 ISO 8601 重复区间 |
| yuc.wiki | ✅ 可用 | **只能走 HTTP**（HTTPS 证书已过期）；路径 `/YYYYMM/`；纯静态 HTML，正则解析 |
| AniList | ✅ 可用 | 每集精确 UTC 时刻的主力；无中文名 |
| Bing 翻译 | ✅ 可用 | 机翻兜底；token 方案，要抓 627KB 页面，**进程内缓存**、一次翻一批 |
| MyMemory | ✅ 可用 | 机翻兜底之兜底，质量明显更差 |
| Bilibili PGC | ⬜ 未接 | 接口已验证可用（`timeline` 的 `pub_ts`） |
| Bangumi API | ❌ 不可达 | DNS 被污染到 Facebook 网段，需要代理（`HTTPS_PROXY`） |
| Jikan | ⚠️ 不稳 | 上游 MAL 常 502/504，只做兜底 |

### 4. 网络

- **Node 的网络是通的，但 PowerShell 的 `Invoke-WebRequest` / `curl.exe` 会失败**
  （schannel 拿不到凭证）。判断某个源能否访问**必须用 Node 复现**，
  否则会得出完全错误的结论。已有工具：`node scripts/diagnose-network.ts`。

### 5. 编码（踩过三次的坑）

- 源码文件一律 UTF-8 无 BOM，用编辑工具改。
- `desktop/*.vbs`、`desktop/*.cmd`、`desktop/*.ps1`：**必须纯 ASCII**（含注释）。
- `.ps1` 若哪天必须写中文，请存成「UTF-8 带 BOM」，否则 PS 5.1 会按 GBK 读。

## 四、验证习惯（新会话应该照做）

```powershell
pnpm exec tsc --noEmit          # 类型检查，必须 0 错误
node scripts/verify.ts          # 离线自检，102 项，不需要联网、不需要装包
node src/server/server.ts       # 启动服务（或 pnpm web）
node scripts/verify-api.ts      # 接口自检，28 项，会真实打源站（含翻译接口）
node scripts/probe-sources.ts   # 数据源结构探测，改抓取器前先跑
node src/server/cli.ts backups  # 看备份与库里的季度
```

**改动的验收标准**：上面四条全绿，并且新功能有对应的自检项。
项目里所有"重要的正确性"都有测试覆盖（深夜番归属、补番归档规则、延期检测的防假警、
手动修正优先级、机翻名的该不该翻 / 写入 / 被官方名替换、备份的 WAL 完整性、.ics 格式），
加功能时请照着加。

## 五、这个项目里最容易改坏的地方

1. **深夜番归属**。任何涉及"这一集算哪天"的改动，都要动 `core/time.ts` + `core/calendar.ts`，
   并且必须保住 `resolveAiringSlot()` 与 `toLiteralJstTime()` 互为逆运算这个性质（有测试）。
2. **多源融合的字段优先级**（`core/merge.ts` 的 `FIELD_PRIORITY`）。
   改优先级会静默改变所有数据的来源，必须核对"覆盖率分布"。
3. **延期检测的防假警**。`server/changes.ts` 里那两条过滤（源优先级、最小时间差）不能删，
   否则每次同步都会刷屏。有专门的测试项和一条接口级测试（连续两次同步必须 0 变更）。
4. **`.ics` 导出的折行**。RFC 5545 要求每行 ≤ 75 字节且按 UTF-8 字节切，
   不要用字符数代替字节数。
5. **机翻名的出处**（`title_cn_source`）。它是「临时译名」能标出来、能被官方名替换的唯一依据。
   踩过的坑：`SubjectSchema` 的 `titleCnSource` 默认是 `'official'`，
   而融合结果在 `titleCn` 为空时仍带着这个默认值 —— UPSERT 若直接写它，
   一次普通同步就会把机翻名的出处**洗成 official**（实测 34 条全中），
   界面上再也提示不出「临时机翻」。修法在 `db.ts` 的 `subjectValues`：
   出处跟着「这次到底有没有给出官方中文名」走，没给出就写 NULL，靠 COALESCE 保住旧值。
6. **备份必须处理 WAL**。只拷 `anime.db` 会丢 `my_anime`（实测：126 部番在、追番 0 条）。
   顺序是 `wal_checkpoint(TRUNCATE)` → 拷主文件 → 连 `-wal`/`-shm` 一起拷。
7. **季度归属绝不能用"谁最后写入"或"落在哪个加宽窗口"决定**。
   实测 2026-07 加宽 7 天后能覆盖到 10-07，拿窗口判会把 10 月新番判给 7 月；
   而按写入顺序判，回填旧季就会把当季条目偷走（当季从 123 部掉到 56 部）。
   唯一起点清楚的判据是：**集数最小的那一集的时刻**（跨源永远一致，因而判定与纠正必然一致、
   幂等、不产生假变更）。实现只有一份：`db.ts` 的 `deriveSeasonFromAirTimes`。
   写入时 `resolveSeasonForWrite` 用它，写库后 `repairSeasonAssignments` 也用它。
   改其中一处必须同时改另一处，否则两者会互相打架并刷出假变更（踩过）。

## 六、当前进度与待办

已完成：数据源验证、核心逻辑、数据层、抓取器 3/5、CLI、Web 界面（5 个视图）、
延期/改档检测、yuc.wiki 校对源、`.ics` 导出、桌面启动器（含诊断日志与调试入口）、
**一键更新数据、临时机翻译名、历史季度回填、自动备份与导出**。

待办（按建议优先级）：

1. **Bilibili PGC Provider** —— 把「国内几点能看」落到每一集（`pub_at_utc`）。
2. **桌面通知** —— 更新前提醒；`.ics` 已覆盖手机端，桌面端还差这一步。
3. **补番计划的界面入口** —— 数据层已支持（`planned_weekday_jst` / `planned_eps_per_day`），
   界面上还没做。
4. **假重复的合并** —— 实测同一部番会落成两条记录；合并要防误合（详见 README「下一步」）。
5. **Bangumi API（需代理）** —— 增益是更准的分集数与制作公司。

明确不做：在线播放/弹幕、社交、云同步账号、Bangumi OAuth、独立手机 App。
