# 在新会话里怎么提要求

> 面向「换一个窗口继续做这个项目」的场景。**你只需要做两件事：把新会话开在 `D:\AI`，然后把下面模板里的话粘进去。**

---

## 一、为什么不能只说「继续做」

新窗口的 agent **看不到我们之前的对话**。它不知道：

- 这个项目有三条硬约束（没有构建步骤、源码 UTF-8 无 BOM、改 `src/` 必须重启服务）；
- 状态与待办都写在 `.scratch/` 里，而不是散在对话里；
- `data/anime.db` 里是**真实在用的追番数据**，不能为测试去动它。

所以新会话的第一件事必须是**去读那几份文档**。下面模板就是干这个的。

---

## 二、开新会话的正确姿势

1. **工作目录开在 `D:\AI`**（不是 `D:\AI\anime-tracker`）。
   这样 `D:\AI\.agents\skills` 里的技能自动可见；项目自己的 `AGENTS.md` 会在 agent 进到项目目录后自动生效。
   （技能只从「项目根 → 当前目录」这条链上收集。开在项目里也能用，只是工作区技能要用绝对路径读。）
2. **第一次说话就把模板粘进去**，别只说「继续」。
3. 如果只是想问个问题，也要说清"只看不改"，否则 agent 可能直接动手。

---

## 三、模板（照着填空就行）

### 报 bug

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：AGENTS.md、.scratch/README.md（开头那个「新会话从这里开始」块）。

现象：<一句话说清哪里不对，最好给出你看到的样子>
期望：<你认为应该是什么样>
复现：<点了什么按钮 / 跑了什么命令>

只诊断，先别改代码，给我根因和方案。
```

> 加「只诊断，先别改代码」很关键：本项目要求 bug **先有会红的反馈环再改**，
> 否则容易出现「改完了但不知道有没有真的好」。

### 提新功能 / 改进

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：AGENTS.md、.scratch/README.md（开头那个「新会话从这里开始」块）。

我想要：<希望做成什么样，越具体越好>
为什么：<你想解决的实际问题，这比功能描述更有用>

先按项目的 issue 流程开票（.scratch/<feature>/issues/），给我看票再动手。
```

> 说清「为什么」能让 agent 判断该不该换个做法 —— 前面几轮里
> 「筛选面板推翻重做」就是因为你说了实际用法才没走弯路。

### 让我先给方案（不写代码）

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：AGENTS.md、.scratch/README.md。

我要做：<目标>
约束：<你已知的边界，比如"别动用户数据""别引新依赖""

动手前先给我实施计划，我点头再开始。
```

### 只想问一件事

```
在 D:\AI\anime-tracker，回复用简体中文。

<问题>

只回答，不要改任何文件。
```

## 四、skill 要不要你点名？

**基本不用。** 规则是：任务匹配到某个 skill 时，agent 会自己加载。
但你想「换个做法」时，点名会很有效 —— 下面是这个项目真正用得上的几个：

| 你的意图 | 可以这样说 | 会加载 |
| --- | --- | --- |
| 报 bug（想让 agent 老实走诊断） | 「用 diagnose 的方式查这个 bug」 | `diagnosing-bugs` |
| 想要新功能但先锁测试 | 「这个改动 test-first」 | `tdd` |
| 设计没把握、想先看手感 | 「先做个原型给我看，认可后再写正式代码」 | `prototype` |
| 让我审你刚写的改动 | 「review 一下这轮的改动」 | `code-review` |
| 想让我把你问住、压力测试一个决定 | 「grill 我」/「拷问一下这个方案」 | `grilling` |
| 要查外部资料（版本、API、别人的做法） | 「研究一下 …，结论落到 docs/」 | `research` |
| 只是想让 agent 省点 token、别乱翻文件 | 「按 token-thrift 的约定做」 | `token-thrift` |

> ⚠️ **不要**点名 `new-project-isolation`：那是新建**别的**项目的脚手架技能。
> 本项目已经建好了（有 `.git`、`AGENTS.md`、`.scratch/`）。

## 五、这个项目的几条「一句话提醒」

新会话不用你说它也会从 `AGENTS.md` 读到，但你在需求里顺手提一句会更保险：

- **别用 PowerShell 改源码** —— PS 5.1 会把中文写成乱码、`-Encoding UTF8` 会加 BOM；
  agent 只能用编辑工具改源码。
- **改了 `src/` 必须重启服务**才生效；`web/` 是静态文件，刷新页面即可。
  判断服务新旧的土办法：`GET /api/runs` 返回 404 就是旧进程。
- **不要为了测试去动 `data/anime.db`**；离线自检用内存库就够了。
- **要动真实数据的活**（清理、迁移、批量改库）：让它**先做 dry-run、先给你看**，
  你点头再执行 —— 票 B 就是这么做的。
- **验收四条命令**：`pnpm exec tsc --noEmit`、`pnpm verify`、`pnpm verify:api`、`pnpm ui:smoke`。
  其中 `verify:api` 有 2 项失败是外部源站 baseline（bangumi-data 与 AniList 从本机拿不到数据），
  不是回归；它**会真的写库**（自己会先备份）。

## 六、如果你希望 Agent 干完顺手提交

Agent **推不了 GitHub**（沙箱拿不到 Windows 凭据，会报 `SEC_E_NO_CREDENTIALS`），
所以流程固定是：

```
你:  <需求，模板见上>
它:  改代码 -> 跑四条验收 -> 本地 git commit
你:  cd D:\AI\anime-tracker && pnpm push      ← 只有这一步需要你
```

想让它「改完直接提交」就在需求里加一句：**「做完跑验收并提交（不用推）」**。
