# 在新会话里怎么提要求

> 换窗口继续做时：把新会话开在 `D:\AI`，然后把下面模板里的话粘进去。

---

## 一、为什么不能只说「继续做」

新窗口的 agent **看不到之前的对话**。项目的现状、硬约束、坑与待办都在
`AGENTS.md` + **`docs/交接说明-第四轮.md`（自包含，只读这一份就够）**。
另外 `data/anime.db` 里是**真实在用的追番数据**，不能为了测试去动它。

---

## 二、开新会话的正确姿势

1. **工作目录开在 `D:\AI`**（不是 `D:\AI\anime-tracker`）。这样 `D:\AI\.agents\skills`
   里的技能自动可见；项目自己的 `AGENTS.md` 会在 agent 进到项目目录后自动生效。
2. **第一次说话就把模板粘进去**，别只说「继续」。
3. 如果只是想问个问题，也要说清「只看不改」，否则 agent 可能直接动手。

---

## 三、模板（照着填空）

### 报 bug

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：D:\AI\anime-tracker\AGENTS.md、D:\AI\anime-tracker\docs\交接说明-第四轮.md。

现象：<一句话说清哪里不对，最好给出你看到的样子>
期望：<你认为应该是什么样>
复现：<点了什么按钮 / 跑了什么命令>

只诊断，先别改代码，给我根因和方案。
```

> 加「只诊断」很关键：本项目要求 bug 先有会红的反馈环再改。

### 提新功能 / 改进

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：D:\AI\anime-tracker\AGENTS.md、D:\AI\anime-tracker\docs\交接说明-第四轮.md。

我想要：<希望做成什么样，越具体越好>
为什么：<你想解决的实际问题，这比功能描述更有用>

按项目的 issue 流程开票（.scratch/<feature>/issues/），给我看票再动手。
```

### 让我先给方案（不写代码）

```
在 D:\AI\anime-tracker 继续做，回复用简体中文。

先读：D:\AI\anime-tracker\AGENTS.md、D:\AI\anime-tracker\docs\交接说明-第四轮.md。

我要做：<目标>
约束：<你已知的边界，比如"别动用户数据"、"别引新依赖">

动手前先给我实施计划，我点头再开始。
```

### 只想问一件事

```
在 D:\AI\anime-tracker，回复用简体中文。

<问题>

只回答，不要改任何文件。
```

## 四、skill 要不要你点名？

**基本不用。** 任务匹配到某个 skill 时，agent 会自己加载。想换做法时点名很有效：

| 你的意图 | 可以这样说 | 会加载 |
| --- | --- | --- |
| 报 bug（老实走诊断） | 「用 diagnose 的方式查这个 bug」 | `diagnosing-bugs` |
| 想要新功能但先锁测试 | 「这个改动 test-first」 | `tdd` |
| 设计没把握、想先看手感 | 「先做个原型给我看」 | `prototype` |
| 审刚写的改动 | 「review 一下这轮的改动」 | `code-review` |
| 压力测试一个决定 | 「grill 我」/「拷问一下这个方案」 | `grilling` |
| 查外部资料 | 「研究一下 …，结论落到 docs/」 | `research` |
| 只想省 token、别乱翻 | 「按 token-thrift 的约定做」 | `token-thrift` |

> ⚠ **不要**点名 `new-project-isolation`：那是新建别的项目的脚手架技能。

## 五、这个项目的几条「一句话提醒」

- **别用 PowerShell 改源码** —— PS 5.1 会毁中文，`-Encoding UTF8` 会加 BOM；只能用编辑工具。
- **改了 `src/` 必须重启服务**；`web/` 是静态文件，刷新页面即可。判断服务新旧：
  `GET /api/runs` 返回 404 就是旧进程。
- **不要为了测试去动 `data/anime.db`**；离线自检用内存库。
- **要动真实数据的活**（清理、迁移、批量改库）：先做 dry-run、先给你看，点头再执行。
- **验收四条**：`pnpm exec tsc --noEmit`、`pnpm verify`、`pnpm verify:api`、`pnpm ui:smoke`。
  `verify:api` 有 2 项已知失败（源站分集波动、`backfill=1` 的断言与实现不一致），不是回归；
  它**会真的写库**，跑完按交接文档第六节清理两条测试追番并 ack 变更。
- **提交**：正常流程是 agent 改完 → 跑验收 → `git commit`（不 push）。
  如果 agent 报 `.git/index.lock` 权限拒绝，那是沙箱 ACL；让它把改动留在工作区，你自己提交。

## 六、推送

Agent 推不了 GitHub（沙箱拿不到 Windows 凭据），只有这一步需要你：

```powershell
cd D:\AI\anime-tracker
pnpm push
```

想让它「改完直接提交」就在需求里加一句：**「做完跑验收并提交（不用推）」**。
